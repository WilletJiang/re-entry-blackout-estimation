# 再入黑障状态估计

English: [README.md](README.md)

## 项目说明

本仓库面向任务 `SE 2317` 所定义的再入黑障状态估计问题。这里的目标是在等离子体鞘层导致的黑障结束后两秒内，恢复可直接用于制导闭环的状态解，同时满足精度、一致性、实时性与存储约束。黑障阶段 GNSS 完全失锁，热环境又会放大惯性器件漂移，因此系统性能取决于常规稳态精度、可观性退化阶段的传播质量、延迟量测处理能力、协方差可信度以及恢复段的收敛速度。

该项目对应一个约束明确、口径清楚、验收条件可复核的估计器实现。任务对象为采用气动控制与 RCS 姿态控制的可重复使用轨道级飞行器，其运动满足六自由度刚体动力学，再入段马赫数范围约为二到十二。传感器工作时序具有显著异步性。IMU 采样频率为四百赫兹。GNSS 频率为十赫兹，并在 `t0 + 120 s` 至 `t0 + 160 s` 之间完全不可用。星敏感器频率为两赫兹，固定延迟一百二十毫秒，并在 `t0 + 130 s` 至 `t0 + 150 s` 之间失效。雷达高度计频率为二十赫兹，固定延迟七十毫秒，仅在高度低于二十五千米时有效。量测还可能出现随机缺测、重尾离群和乱序到达。

## 估计器设计

当前实现采用二十四状态误差状态平方根 EKF。状态量包含位置、速度、姿态、角速度、陀螺零偏、加速度计零偏，以及用于吸收模型失配的气动力残差与气动力矩残差。协方差传播始终保持平方根形式，并通过基于 QR 的时间更新控制数值条件，从而在长时间黑障传播以及黑障结束后的快速重捕获阶段维持稳定性。平动传播采用捷联惯导形式。真值传播与滤波器侧标称线性化调用同一套标称气动与 RCS 合成模块，以减少仿真与估计之间本可避免的确定性动力学偏差。

延迟处理是该仓库的核心设计约束。对于延迟到达或乱序到达的量测，系统通过固定时滞历史缓冲执行回退、更新、确定性重放，并严格在量测时间戳处完成校正。GNSS PVT、原始 GNSS、星敏感器和雷达高度计均走同一条时间对齐路径。这样做之后，即使到达顺序偏离物理顺序，状态与协方差仍然保持时间一致。针对黑障本身导致的可观性缺失，仓库还实现了固定时滞 RTS 平滑，以便在信号恢复后利用新增信息改进黑障尾段的状态估计。

GNSS 量测模型提供两种工作方式。基础方式直接使用位置与速度解算结果。黑障结束时，基础路径会在退出时刻立即执行一次重捕获更新，且该次更新的速度协方差与常规 PVT 更新保持一致，因此整个两秒恢复窗口都遵循同一套传感器口径。紧耦合方式则直接使用伪距和多普勒原始量测。在这一路径中，伪距行不会直接更新速度，多普勒最弱方向投影只在黑障结束后的两秒恢复窗口内启用。这样既保留了黑障前常规跟踪阶段的完整平动信息，又能在恢复段最脆弱的时刻抑制几何退化带来的噪声注入。除此之外，系统还配置了卡方门限、Student t 型协方差膨胀、可选的基于创新的自适应估计，以及黑障前加速度计零偏预校准机制，用于在强非理想量测条件下维持一致性与可恢复性。

## 验收口径与验证结果

仓库的验收逻辑严格遵循 `tasks.md` 所定义的任务窗口。核心精度评估只在黑障结束后的两秒恢复段内进行。当前 harness 的逐次通过判定基于该窗口内各状态范数等价三西格玛上界的最大值：位置不超过四十米，速度不超过零点五米每秒，姿态不超过零点一五度，陀螺零偏不超过零点零零五度每秒，加速度计零偏不超过一百二十微 g。恢复窗口 RMS 误差仍然保留在输出中，但其角色是诊断量而不是通过判定本身。通过标准同时考察误差水平与协方差可信度，因为协方差系统性乐观会直接增加制导侧风险。NEES 与 NIS 因此被纳入常规验证流程，用于检验估计误差与协方差之间是否保持统计一致。

harness 默认使用十秒固定时滞历史长度，并把 `Estimator::health()` 的历史缓冲计数与内存估计峰值写入汇总 csv。`verification.md` 中 2026 年 3 月 11 日的验证数字仍可作为历史基线，但它们生成于当前验收口径与汇总字段对齐之前。若要给出当前状态的正式结论，应在新口径下重新跑完整验证。

## 构建与复现

仓库以稳定版 Rust 为目标环境。若需要复现基准与诊断流程，常规发布构建即可满足要求。

```bash
cargo build --release
```

默认特性集包含仿真与诊断功能。若只需要核心库，可采用更精简的 flight 构建方式。

```bash
cargo test --no-default-features --features flight
```

主验证入口是 Monte Carlo harness。默认执行 PVT 路径。设置 `TIGHT=1` 后，将启用基于伪距和多普勒的紧耦合更新。

```bash
cargo run --release --bin harness -- 500
TIGHT=1 cargo run --release --bin harness -- 500
```

若需要复现实例或跟踪单个随机种子，可使用如下命令。

```bash
cargo run --release --bin repro -- 231
TIGHT=1 cargo run --release --bin repro -- 231
```

若需要诊断传播链和量测处理时序，可进一步打开跟踪开关。

```bash
TRACE=1 cargo run --release --bin repro -- 206
TRACE_GNSS=1 TIGHT=1 cargo run --release --bin repro -- 231
```

harness 会在配置的输出目录中生成汇总 csv、分阶段一致性诊断、分状态块一致性诊断、黑障恢复窗口统计以及 svg 图形结果。汇总文件同时记录恢复窗口 RMS 诊断、恢复窗口三西格玛最大值、平滑后恢复窗口 RMS 诊断以及历史缓冲内存峰值。若启用黑障轨迹记录，轨迹中还会包含位置误差、速度误差、位置三西格玛、速度三西格玛与 RV NEES，并统一使用与通过判定一致的统计口径，便于把恢复段回归问题精确定位到具体时刻。

## 仓库结构

估计器主体位于 `src` 下，内部按传播、量测更新、历史缓冲、校准、鲁棒性支持与平滑等职责拆分。仿真与评测代码同样位于 `src` 下，负责真值生成、传感器合成、Monte Carlo 执行与指标汇总。`physics.rs` 提供共享的标称动力学模块。`data.rs` 负责从 `data` 读取飞行器参数表、气动系数表和 RCS 预览数据。`types.rs` 定义公共状态与噪声参数结构。启用诊断特性后，`plot.rs` 负责输出 csv 与 svg 结果。

除主文档外，仓库还配套三份说明文本。`design.md` 解释估计器设计决策与数值稳定性处理。`interface.md` 说明时间戳约定以及面向飞行软件的调用方式。`verification.md` 给出可复现实验流程与当前基准结果。`docs` 下报告子目录中的排版报告则提供更完整的数学推导和实验叙述。
